## Delivered changes

- A selected eligible count location has one primary Scan location QR action. Exact-name/code identification is a labelled fallback; Skip is secondary. The duplicate Start form and selected-location Count this location link are removed. Identification still uses the existing `begin` command, which already starts the run; no new accounting prerequisite was added. Results, scope, assignments and return-of-work controls remain. Navigation offers counting only for eligible owned locations, and assignment/review or results to other viewers.
- Stocktaking shows its local progress once and omits the duplicate global reminder. The reminder and badge continue elsewhere, with assignment-aware wording. An online, empty outbox has quiet connection status and secondary help/refresh. Waiting counts promote Send saved counts; offline status promotes retry; rejected counts are labelled as needing correction instead of awaiting confirmation. Queue records, receipts and partitions are unchanged.
- Assignment/schedule selectors, visible ownership and observation/reviewer attribution include usernames alongside names. Snapshot additions preserve original counter/reviewer IDs and eligibility rules; inactive people remain attributable in history.
- Unsaved extra-product rows can be removed. Baseline rows cannot, and an observation with a saved pending/confirmed receipt cannot have its extra rows removed. Removing an extra persists the revised draft; reload does not restore it. Baseline zero, physical totals, affected quantities/conditions and retained extras survive restoration. Immutable observations and submitted request records are never deleted.
- Location field types read Text, Number and Choice list, with short examples. Choices appear only for Choice list, and switching types preserves the typed choices. Label, type, choices, order, required/enabled/directions flags, field identity and original revision survive ordinary server rejection and reload. Field drafts are scoped to account/site storage and dataset. Successful saves clear only that field's draft.
- A secondary, explicit **Discard this draft and load latest field** action exits a stale-revision loop. It retrieves the latest saved definition and discards only the selected unsaved draft; it does not silently rebase old edits. An unconfirmed saved request blocks discard. Failed refresh/storage keeps the draft. Other drafts and pending evidence remain intact.
- Guided setup reports **Light count not configured**, explains that mappings do not establish a physical count, and provides an authorized Hardware link or asks for someone with access. Zero-output controllers cannot be selected for Start; valid controllers retain Start/resume. Hardware now separately displays declared/configured outputs and mapped locations instead of substituting mappings for missing output counts. No physical count is inferred or changed. Manual locations, setup sessions, physical confirmation, QR binding, generations and display ownership remain unchanged.
- Offline asset cache advances to v13 for the count client changes. Product copy contains no development-phase instructions.
